# GameScores — Render production deployment

## What was fixed

- Disabled Vite HMR WebSocket in the hosted app. GameScores uses its own `/ws` WebSocket.
- Added `/api/health` for Render health checks.
- Server now uses Render's `PORT` environment variable.
- Production scraper interval defaults to 30 seconds (minimum 15 seconds).
- Added graceful shutdown for the scraper, WebSocket server, and Facebook publisher queue.
- Frontend WebSocket reconnects safely with backoff and no longer calls `close()` while the socket is still connecting.
- Fixed the frontend to accept the server's `{ matches, count, timestamp }` WebSocket payload.
- Removed the Facebook Page access token from the committed JSON data file.
- Added Render Postgres to the Blueprint for persistent match/publisher history.
- Added `.env.example` with the production variables.

## Render

The included `render.yaml` is configured for:

- Web service: `sports-scores-publisher`
- Compute: `0.5c-512mb` (paid, always-on)
- Build: `npm install && npm run build`
- Start: `npm start`
- Port: `10000`
- Health check: `/api/health`
- Postgres: `gamescores-db`
- Scraping interval: `30` seconds

Render's current compute plan ID `0.5c-512mb` is the current name for the legacy Starter plan.

## Facebook

Set these in Render:

- `FB_PAGE_ID` = your Facebook Page ID
- `FB_PAGE_ACCESS_TOKEN` = your current Page access token

The token is intentionally NOT stored in GitHub or `data/sports_db.json`.

## Optional services

- `REDIS_URL` is optional. The app falls back to memory cache.
- `SCRAPLING_SERVICE_URL` is optional. The native TypeScript Flashscore client remains the fallback.
- `API_ADMIN_KEY` is generated by Render in the included Blueprint.

## Important

If the existing Render service already has a PostgreSQL database, do not create a second database. Instead, point `DATABASE_URL` at the existing database connection string.

After deploying, check:

`https://YOUR-SERVICE.onrender.com/api/health`

Expected response:

```json
{
  "ok": true,
  "service": "gamescores"
}
```

Then open the dashboard and confirm:

1. Live matches update.
2. WebSocket shows connected.
3. Scrape cycles increase.
4. Facebook publisher queue is running.
5. Automatic publishing works without the dashboard being open.
